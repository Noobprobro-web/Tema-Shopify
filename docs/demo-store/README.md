# Demo store kit (fresh development store)

Everything here is local preparation. Nothing was imported, no store was contacted. Johandry imports into a NEW, clean development store (not `tema-qkqpke0j`).

| File | Purpose |
|---|---|
| `products.csv` | 24 products / 691 variant rows. 21 active, 3 `[TEST]` drafts. Generated by `scripts/build-products-csv.mjs`. |
| `collections.md` | 8 automatic collections plus 3 state-test collections (tag conditions, exact handles) |
| `pages.md` | `about`, `contact`, `faq` bodies and policies |

| `blog.md` | Optional blog and 3 articles |
| `scripts/verify-products-csv.mjs` | Offline check: header, SKU/handle uniqueness, variant counts, fixtures, tag counts |

Run: `node docs/demo-store/scripts/verify-products-csv.mjs` (exit code 0 = all pass).

## Import order
1. Settings > Store currency: USD (prices are plain numbers, no conversion). Single location only (the `Variant Inventory Qty` column is ignored with several locations; the sold-out fixture then needs qty 0 set by hand).
2. Products > Import: compare the header of `products.csv` with the sample file Shopify offers on that screen. Shopify's help now documents renamed columns ("URL handle", "Description", "Price"...); the classic names used here (`Handle`, `Body (HTML)`, `Variant Price`...) are the ones the repo's earlier import kit used, but I could not download the live sample, so check it. If it complains, rename columns only; the data layout does not change. Product Category is left blank (needs Shopify taxonomy values).
3. Create collections (`collections.md`), pages (`pages.md`), policies, then menus (`menus.md`). Blog is optional.
4. Add images (below), then Online Store > Themes > upload the theme, pick the preset, and apply "Theme settings to point" below.
5. Publish nothing from the drafts. Test products stay `draft`.

## Images
`Image Src` is empty on purpose (no invented URLs). Options: (a) Products > product > upload your own photos; (b) in the development store use Shopify's sample product images from "Add sample data"/mock catalog; (c) upload files to Content > Files and attach by hand. Product images needed: all active products EXCEPT `leather-belt`; `doppio-trench` needs 12; other products need 1-3. `silk-twill-square` should have an image but no description. ## Theme settings (default theme no longer depends on demo handles)
The default root templates must not contain handles that exist only in the demo (`the-autumn-series`, `/pages/about`, `/pages/contact`): they would 404 on a clean install and break the rule that the demo equals a fresh install. Mount the demo with the SAME JSON as the theme (plus catalog, pages and menus); do not add demo-only links by hand.
Root `templates/index.json`:
- `hero_editorial` secondary button points to `/collections` ("Browse collections").
- `brand_manifesto.button_url` and `bento_editorial.link` are empty (their buttons are hidden).
- `bento_discovery` card_featured uses `collection: "all"` and an empty `link` (falls back to the collection URL).
- `curated_showcase` tabs all use `collection: "all"`.
- `bento_product.product` `oversized-alpaca-knit`; `complete-the-look` -> `doppio-trench`, `cashmere-rib-crew`, `wrap-wool-skirt`.
`templates/page.faq.json`: the CTA button URL is empty (button hidden).
`listings/*/templates/*.json`: the presets also use only `collection: "all"`, `/collections/all` or empty URLs.
`sections/header-group.json`: `menu: main-menu`, `menu_item: Catalog`, mega-menu `link_1`/`link_2` (currently `/collections/all`; point to `new-forms` and `tailoring` in the editor to match images). `sections/footer-group.json`: `menu: footer`.
`sections/main-404.liquid` uses `collections['all']`: fine.
