# R-A / R-B scoped read-only preview harness

This fresh Playwright runner targets only the approved previews on `tema-qkqpke0j.myshopify.com`: Sartorial `190232297715`, Imprint `190232330483`, and Archive `190232363251`. The coordinator must verify that they are still unpublished before a session.

**`--read-only` runs scoped smoke checks; `--inventory` runs resource diagnostics only. `--cart` exits with `CART_MODE_DISABLED_PENDING_REVIEW` before credentials are read, Playwright is imported or a browser is launched. B-03/B-04 mutation tests remain pending.** There is no cart mutation implementation in this release.

## Preparation and command

Use the prepared worktree dependencies and Chromium. `STOREFRONT_PASSWORD` and `SHOPIFY_CLI_THEME_TOKEN` must exist locally. The token is only checked for presence; this browser runner does not use it. Never pass values on the command line, write them to a file or print them.

```powershell
node agent-comms/outbox-gpt/harness-GPT-RA-RB-001/run.mjs --read-only
node agent-comms/outbox-gpt/harness-GPT-RA-RB-001/run.mjs --inventory
```

Choose exactly one mode. Optional `--theme=190232297715` (or one of the other two IDs above) limits either mode. Host, routes and IDs are fixed. One nonpersistent BrowserContext is created per preview; service workers are blocked. No storageState, cookies, HAR, trace, screenshot, raw exception, response body, node HTML, selector, DOM text or form value is saved. JSON under `results/` contains fixed identifiers/enums, counts, booleans and timestamps; explicit inventory mode additionally contains guarded known hosts and salted resource fingerprints described below. Neither mode stores a raw pathname, complete URL, query or URL fragment. Console output is a result-file basename and fixed enum.

## Global request policy

Every routed browser request passes a method/host/path allowlist, including requests from subframes and popups. Requests from any frame other than the original page's main frame are denied. Popups are closed, WebSockets are denied, and all checkout/pay/payment endpoints or known payment hosts are denied. Unknown hosts and paths are denied.

The browser permits only GET/HEAD reads and never receives the password in a form or DOM field. Authentication uses one BrowserContext API POST to exact same-origin `/password`, with no query/hash, `maxRedirects: 0` and `maxRetries: 0`. The policy consumes its one-use permission before sending it. Only 302/303 is accepted; 307/308 is never replayed. Location must resolve to the exact store origin and `/` pathname without userinfo. Its search/hash are discarded, never persisted and never used to navigate. No Location is followed by the API client. Cookies stay only in that context's memory. The next browser GET is constructed locally from the fixed store origin, `/` and exactly the selected preview ID, then `Shopify.theme.id` must match before any test. No external mutation or cart mutation is allowed.

Same-store reads are limited to fixed suite pages, cart JSON, the fixed product JSON, search suggestions, recommendations and static resources. Static resources require a bounded ASCII path, no encoded path, and a CSS/JS/image/font/video extension from the fixed list in the runner. Permitted theme roots are all of `/cdn/shop/t/<authorized-preview-id>/` for exactly `190232297715`, `190232330483` and `190232363251`; this includes the selected session ID and never admits arbitrary numeric IDs. `/cdn/shop/files/`, `/cdn/shop/products/` and same-origin Shopify cloud static resource directories are also permitted. Results classify these as `authorized_preview_theme_asset`, `store_media_asset` or `store_platform_asset`. A root using any other ID remains blocked even if the extension is static. The browser page's identity must still match the selected session theme before tests. This change is not evidence that the 38 same-origin scripts observed in the prior run are resolved: a new reviewed run is necessary. Checkout/pay/payment, account and admin paths are always denied, as are mutations and document routes outside the suite. No complete R-A/R-B acceptance is claimed.

External reads permit only exact host `cdn.shopify.com` and exact path `/shopifycloud/model-viewer-ui/assets/v1.0/model-viewer-ui.css`, already referenced in the repo layout. There are no external prefix patterns, wildcard hosts, arbitrary filenames or runtime-discovered allowlist entries. Every other external font/media/script/style is blocked. Every external query and fragment is removed before fetching. Resource filtering can still affect fonts/media/scripts/styles and therefore test results; any resource-dependent failure requires review of the block counts and cannot automatically be attributed to the theme. Expanding the external list requires a reviewed, fixed path list rather than trusting page-supplied paths.

Each external hop uses a fresh APIRequestContext with an empty cookie jar, no HTTP credentials, and explicit `Accept: */*` and constant `User-Agent` headers only. Browser Cookie, Authorization, Referer, Origin and custom headers are never copied. Each client is disposed after the hop; external Set-Cookie/WWW-Authenticate response headers are not fulfilled back into the browser. This avoids cookie/header inheritance even across redirects. A resource that does not work under those headers fails closed; no fallback copies browser headers.

Playwright routing does not observe every automatic redirect hop. Therefore the browser router never calls `route.continue`: it fetches a single GET/HEAD hop with `maxRedirects: 0`, validates any Location against the same-origin/path allowlist, rejects every cross-origin hop, follows only validated read hops up to a fixed limit, and fulfills only a final response without Location/Refresh headers. Browser POST/other mutations are denied before fetch. Popups/subframes cannot bypass this policy.

BrowserContext routing does not intercept APIRequestContext requests. Therefore every API call uses the explicit `requestViaPolicy` wrapper, which applies the same policy, shares only the in-memory context cookie jar and sets `maxRedirects: 0`/`maxRetries: 0`. Its only POST is the one-use auth endpoint above; its only other call is GET `/cart.js`. Any API Location is validated, but never followed; non-auth redirects fail. There are no raw `page.request` calls. The browser never executes a POST redirect, so a 307/308 cannot resend the password.

All non-GET decisions (including allowed HEAD/auth POST) and all blocked decisions are classified with fixed method/resource/context/host-class/path-class/reason enums. Raw hosts outside the fixed list, URL strings, query strings, headers, cookies, request bodies and form values are never recorded. The log is capped at 1000 entries with an omitted-count field. Every page used for tests must also verify `Shopify.theme.id` against its allowed ID; a mismatch fails closed.

`deniedResourceSummary` adds aggregate diagnostics only. Each denied occurrence contributes to fixed root categories `authorized_preview_theme_root`, `other_theme_root`, `files`, `products`, `platform`, `other_store` or `external`, suffix class `known_static`/`other`, static-ASCII predicate and length-limit booleans, a closed reason enum and a count. `sourceSuffix` is restricted to `base_css`, `theme_js`, `shopify_xr_js`, `product_zoom_js` or `other`, derived from literal suffixes referenced in local source. The pathname is compared only in memory; the enum does not identify its full route, prove asset identity or certify a defect. Membership in the three-ID whitelist is also checked only in memory: a request with an authorized root can still be denied by another guard. The aggregate records no request URL, path, query, raw filename or extracted theme ID. The ASCII flag uses the same permitted character set as the static path policy, and malformed/unavailable addresses keep false flags. Counts are denied request occurrences, not unique resources or counts of all allowed assets. These categories can locate the policy mismatch but cannot prove a script's ownership or certify a theme defect. They never build an allowlist from page-discovered resources.

## Inventory diagnostic

`--inventory` uses the same authentication, context isolation and request policy. It loads the fixed home, collection and product pages and waits for their load state; it does not run the functional, layout, axe, keyboard or cart suite. No allowlist is expanded. Its JSON result is always `scopeResult: inventory_only`; `executionResult` separately reports completed/failed, and a runtime failure still produces a nonzero exit code. This is diagnostic evidence, never R-A/R-B acceptance.

Only denied browser GET/HEAD requests of static resource kinds (script, stylesheet, image, font, media or texttrack) enter `inventoryResources`. Rows contain method, fixed resource/host/root categories, a known host or null, a `resourceFingerprint` or null, closed block/redaction reasons, a redacted flag and count. The pathname is never stored, even when the secret guard accepts it. In memory it must have an allowed static suffix, the bounded ASCII character set and maximum length of 1024. A safe candidate produces SHA-256 of a private per-run salt plus known host and pathname, excluding query/fragment. The salt is never emitted and is distinct from run/file IDs, preventing cross-run correlation. The one-way fingerprint does not reveal the route; it is an opaque deduplication key within that run. Unknown/unsafe candidates emit only fixed categories/counts with host and fingerprint null. There is no raw filename or extracted-ID field.

Known inventory hosts are the exact store host, `cdn.shopify.com`, `cdn.shopifycdn.net`, `fonts.shopifycdn.com`, `fonts.googleapis.com` and `fonts.gstatic.com`; this observability set grants no network permission. Before hashing a candidate, a common guard compares normalized host/path variants against nonempty environment values whose names match token/password/passwd/pwd/cookie/secret/auth/credential/key. It uses NFKC, trim, case folding and at most three URL-decode steps. It never emits secret values. A match, unavailable guard, unsafe address/format, excessive length or nonstatic suffix produces no host/fingerprint and a fixed reason. Emitted host/fingerprint fields are guarded again immediately before JSON writing. Query, URL fragment, userinfo, headers, cookies, bodies and form values are never copied to output.

Rows are deduplicated after redaction/hashing and capped at 100 per session. `inventoryCounters` reports eligible, redacted and truncated occurrences; counts are occurrences rather than unique source ownership. The guard covers known environment secrets and format constraints; fingerprints do not authorize resources, expose routes for a future allowlist, or establish ownership by the selected theme. Every proposed policy change still requires independent review.
